- нейминг
	- максимально короткий для текущего контекста
		- например в `infrastructure::app_settings::file_repo` структура репозитория называется просто Repo,
		  т.к. по контексту понятно, что репозиторий для настроек приложения и что он хранится в виде файла
		- В `infrastructure::app_settings` он уже реэкспортируется как FileRepo,
		  т.к. там может быть не только файловая реализации
		- В `infrastructure` он реэкспортируется как FileRepoOfAppSettings,
		  т.к. на этом уровне есть уже много разных репозиториев для разных данных'
	- от более важного к менее
		- Привычный порядок - сначала свойства, а в конце сам объект: AppSettings File Repo
		- Но лучше писать сначала главное слово, а потом свойства по убыванию важности: RepoOfAppSettingsInFile
		- т.к. при написании кода в первую очередь в голову приходит сам объект, а потом уже уточнения какой именно
